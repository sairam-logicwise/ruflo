## Critical

### C1. The published CLI will fail to install for every user

`v3/@claude-flow/cli/package.json` now declares `"@claude-flow/docops": "3.0.0-alpha.1"` as a regular dependency. That package **does not exist on npm** — confirmed, registry returns 404. Neither `scripts/prepare-root-publish.mjs` nor `v3/@claude-flow/cli/scripts/prepare-publish.mjs` mentions docops, so nothing bundles it.

Local development works because the pnpm workspace glob `@claude-flow/*` links it. Publishing does not. The next `npm publish` ships a CLI whose install 404s, breaking `npx ruflo@latest` for everyone.

`CLAUDE.md` is explicit that internal `@claude-flow/*` packages are "bundled into the public artifacts; do not publish them standalone."

**Fix:** bundle docops in the publish prep, the way other internal packages are handled. Verify with `npm pack` and a clean install from the tarball before any release.

### C2. Malformed YAML fails open — the pre-commit gate can be disabled by one bad file

`v3/@claude-flow/docops/src/frontmatter.ts:47` calls `js-yaml` `load` unguarded. It throws on malformed input. `validateRecordFile` does not catch it, and the `try/catch` at `scripts/hooks/pre-commit-lib.mjs:33-37` wraps only `readStagedContent`, not the validate call. The throw reaches the hook's top-level handler, which prints "hook crashed… allowing the commit" and **exits 0**.

**Attack:** stage a task record with frontmatter `citations: [unclosed`. The record has no valid citations — precisely what the contract exists to block — and the hook waves through the entire commit, every other record included. The same throw also kills `ruflo record validate` (`records.ts:429`) and `record list` (`:392`), so the command whose job is reporting invalid records dies on the first one.

**Fix:** catch the parse error in `parseRecordFile` and surface it as a validation failure rather than a throw. Separately, the hook's crash handler should exit 1 when record paths were in scope — failing open on a hook bug is acceptable for a code-only commit, not for the gate's own input.

### C3. The tokenizer is not the encoding the code says it is

`v3/@claude-flow/cli/src/ruvector/token-count.ts` documents cl100k_base twice, in the module comment and the function doc. `import { encode } from 'gpt-tokenizer'` resolves to **o200k_base**.

Verified directly on a mixed code/Unicode string: default import → 23 tokens, `cl100k_base` → 25, `o200k_base` → 23.

The existing test uses `'function add(a, b) { return a + b; }'`, which counts 13 under all three encodings, so nothing pins the behaviour. A `gpt-tokenizer` minor bump could silently move every quote we produce.

**Fix:** import the encoding explicitly — `gpt-tokenizer/encoding/cl100k_base` — and add a test on a string where the encodings differ. The subpath import also avoids pulling the full 29MB package.

### C4. A fourth price table is live, and `predictedCostUsd` is ~100x wrong on the OpenRouter path

T12 required collapsing to one price source. `gaia-bench.ts`'s duplicate was genuinely deleted, but `v3/@claude-flow/cli/assets/model-router/openrouter-alts.json` still carries per-tier pricing. Confirmed contents:

| Tier | openrouter-alts.json | MODEL_PRICES | Ratio |
|---|---|---|---|
| haiku | in 0.01 / out 0.03 | in 1.00 / out 5.00 | ~100x / ~167x |
| sonnet | in 2.00 / out 8.00 | in 3.00 / out 15.00 | 1.5x / ~1.9x |

`model-router.ts:761,766` prices the **tier label** against `MODEL_PRICES`, but under `CLAUDE_FLOW_ROUTER_PROVIDER=openrouter` the model actually executed is the alt. A field named `predictedCostUsd` is then overstated by two orders of magnitude.

**Fix:** resolve through `resolveExecutionProvider()` and price the concrete model slug, not the tier label.

## Important

### Correctness

1. **The generated JSON Schemas enforce only half the citation contract.** `schemas/task.schema.json:23-29` has `minItems: 1` but not the "at least one REQ or DEC" rule — Zod `.refine()` has no JSON Schema representation and `zodToJsonSchema` drops it silently. An editor validating against this file green-lights `citations: [TASK-002]`. The Zod path is correct; the artifact we hand to editors is weaker than the code. Post-process in `generate-json-schemas.ts` and assert it in the test.
2. **`id` pattern is too loose in the generated schema.** `^(REQ|DEC|TASK)-\d+$` at line 9 means the schema accepts `id: REQ-001` inside a task record.
3. **Citations `$ref` into the task's own `id` definition** (`task.schema.json:26`). Narrowing the id pattern would silently make citations TASK-only. Emit a standalone `recordId` definition.
4. **The content hash is computed but never verified.** Nothing recomputes it on write or checks it on read; `validateRecord` only checks it is 64 hex characters. A stale or fabricated hash validates cleanly, so its drift-detection purpose is unmet.
5. **The content hash is not CRLF-stable.** Identical content hashes differently under `\r\n`. With `core.autocrlf` on Windows — a documented pain point in this repo — the same record yields different digests per checkout. Normalise line endings before hashing.
6. **Corpus exclusion accounting does not balance** (`estimator/corpus.ts:96-140`). `corpusSize + excludedNoMatch + excludedNoTokens` equals the deduplicated decision count, not the raw count. In the "latest wins" test one decision vanishes unexplained. Orphan outcomes are dropped uncounted. Add `duplicateDecisions` and `orphanOutcomes`.
7. **Corpus zero-token filter uses AND where OR is probably right** (`corpus.ts:126`). `{input: 5000, output: 0}` is kept. For cost learning the output half is the expensive one, so that row teaches a wrong cost.
8. **Corpus row validation is type-tag deep only** (`corpus.ts:84-88`). `{"type":"decision"}` with no `task` or `complexity` counts as well-formed and enters the corpus with `undefined` fields.
9. **`predictedCostUsd` passes `outputTokens: 0`** (`model-router.ts:755-770`). Output is 5x the input rate on every Claude entry and usually dominates, so this is a floor, not a prediction. ADR-150's `cost < 1%` promotion gate reads this field.
10. **Concurrent record creation silently overwrites** (`records.ts:58-66`). `nextId` reads the directory, then `writeFileSync` clobbers. Two agents creating requirements in parallel — the documented workflow here — both compute the same id and the second destroys the first. Use `{ flag: 'wx' }` and retry on `EEXIST`.

### Tooling and supply chain

11. **`cd v3/@claude-flow/docops && npm test` runs zero tests.** All four suites fail with `Cannot find module __tests__/setup.ts` — the package has no vitest config and inherits `v3/vitest.config.ts:18`, which resolves the setup path against the wrong root. The tests are fine: 34 pass when run from `v3/`. Add a package-local `vitest.config.ts` so the documented command works and coverage is unambiguous.
12. **`js-yaml: ">=4.3.0"` is unbounded and currently resolves to 5.4.2** — a major version past anything tested, on the parser that reads untrusted record files. Use `^4.3.0`.
13. **CI installs `graphifyy` unpinned.** The workflow comment says the "$0, no LLM" behaviour was verified by reading v0.7.16; PyPI latest is 0.9.65, released 2026-09-20. CI runs a version nobody verified. (The double-y package name is legitimate and official — not a typosquat.) Pin it.
14. **CI caches a graph that failed the freshness check.** `graph-refresh.yml:81` saves with `if: always()`, so a graph that failed the step-4 assertion is still cached, and `restore-keys: graphify-out-` picks the most recent entry next run. The cache poisons itself. Use `if: success()`.

### Robustness

15. **Pre-commit skips any record file git quotes.** With default `core.quotePath`, a non-ASCII filename comes back as `"docs/tasks/t\303\241sk.md"`, which the path pattern never matches, so the file is silently unvalidated. Use `-z` and split on `\0`.
16. **The hook installer silently destroys existing hooks** (`install-git-hooks.mjs:32-38`). It runs from `prepare` on every `npm install` and overwrites unconditionally. A contributor using husky or a personal `pre-commit` loses it with no message. Compare contents and require `--force` when they differ.
17. **Five training scripts now hard-crash on an unknown model** rather than degrading — `train-bundled-krr.mjs:45`, `auto-retrain-router.mjs:81,195`, `calibration-check.mjs:69`, `train-calibrator.mjs:45`, `train-bundled-fastgrnn.mjs:39`. All current models are covered so nothing breaks today, but `auto-retrain` reads live corpora. Decide explicitly whether batch retraining aborts or skips, and fix the stale `$1/Mtok` comment at `train-bundled-krr.mjs:43`.
18. **`length / 4` still lives in four places** — `commands/hooks.ts:4956-4957`, `appliance/gguf-engine.ts:307,309`, `mcp-server.ts:134`. `countTokens` has exactly one production caller. T12 defect 3 is partially delivered.

## Suggestions

- `records.ts` is bloated by duplication rather than by the feature: the three `new` actions are the same 30 lines with a different frontmatter literal. A `makeNewCommand(kind, buildFrontmatter)` factory drops ~120 lines and guarantees the concurrency fix lands in all three.
- `TaskSchema` uses `.strict().refine()`, producing a `ZodEffects` that cannot be `.extend()`ed — T8/T13/T18 will have to edit the file rather than compose. Export the object schema separately and apply the refine last.
- Add a `schemaVersion` field. `.strict()` with no version means a record written by a newer writer hard-fails an older reader.
- `base.ts:29` — `REQ-1` and `REQ-001` are distinct ids; citations will not match across zero-padding.
- Cap input size before YAML parsing. A 300-byte billion-laughs frontmatter expands to ~23MB in under a millisecond. Irrelevant locally, a CI OOM vector once validation runs on untrusted PR content.
- `docops/tsconfig.json:7` — `include: ["src/**/*"]` leaves `scripts/` and `__tests__/` untypechecked by `npm run build`.
- docops has no `files` field; a publish would ship tests and vendor sources.
- `graph-refresh.yml` has no `permissions:` block. Add `permissions: contents: read`.

## What was done well

Worth recording, because these were deliberate choices and should not be undone in the fixes:

- **Path traversal is closed structurally.** Filenames are built from an internally generated id and a slug that collapses everything outside `[a-z0-9]`, and the read path matches ids against directory listings rather than joining user input into a path. `PathValidator` would add ceremony, not safety.
- **No shell anywhere.** `execFileSync` with argv arrays throughout; no `shell: true`. Filenames with quotes or semicolons are inert.
- **The hook validates the staged blob** via `git show :<path>` rather than the working tree, closing the add-then-edit race that most pre-commit hooks have. The comment explains why.
- **The citation contract is genuinely enforced in Zod**, both halves, and the tests assert the negative cases including "cites only tasks" with a message-content assertion.
- **YAML safety confirmed empirically:** `!!js/function` rejected, `__proto__` does not pollute.
- **The gaia-bench duplicate price table was deleted, not aliased**, and the disagreement was resolved to the correct value — $1/$5 is Anthropic's published Haiku 4.5 rate; the $0.25/$1.25 it replaced was Haiku 3's.
- **`router-trajectory.ts:280-287`** narrows its catch to `UnknownModelPriceError`, rethrows everything else, and drops only the cost field. Textbook best-effort telemetry.
- **`dist/` is correctly gitignored** — build output is not being committed.
