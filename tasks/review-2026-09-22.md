## Blockers

### B1. C4's 100x pricing bug returns in production, and the C4 test cannot catch it

Declared fixed as "the openrouter-alts.json cwd-resolution gap". It is not fixed. It was worked around in the test.

`model-router.ts:99-116` resolves the alts file from exactly three places: an explicit env var, and two paths relative to `process.cwd()`. The C4 regression test sets that env var (`predicted-cost-openrouter-c4.test.ts:34`) to an `import.meta.url`-resolved path, so it passes regardless of whether cwd resolution works.

**Production consequence.** A user runs `npx ruflo` from their own project. Neither cwd candidate exists. `loadOpenRouterAlts` returns null silently — the `catch` is empty by design. `resolveExecutionProvider` then returns `{provider: 'openrouter'}` with no `openrouterModel`, so pricing falls back to the tier label. That is exactly the bug C4 fixed: haiku priced at $1.00/$5.00 instead of $0.01/$0.03, a ~100x overstatement, in a field named `predictedCostUsd`.

So the previous review's Critical 4 is only fixed when the repo is the cwd.

**Fix:** resolve the asset relative to the module, not the process. The comment at `:103-104` says `import.meta.url` was avoided for CJS/ESM compatibility — that is a real constraint, but `require.resolve`-style package-relative lookup or bundling the asset into `dist/` both solve it. Then delete the env pin from the test so it exercises the real path, keeping the env var only as an override.

### B2. CRLF checkouts are hard-blocked on Windows — I5 is only half fixed

`computeContentHash` is CRLF-stable in isolation (`content-hash.ts:21`), and the test asserts that. But the scenario I5 was actually filed for — a Windows checkout with `core.autocrlf` — still fails. Verified by execution:

```
unit: hash(LF) === hash(CRLF body)?  true
file-level LF   valid?               true
file-level CRLF valid?               false  <- ContentHashMismatchError
CRLF parsed body starts with:        "\r\n# Title\r\nS"
```

`frontmatter.ts:55` uses `/^---\r?\n([\s\S]*?)\r?\n---\r?\n+/`. The trailing `\r?\n+` consumes one `\r\n`, then `\n+` cannot match the next `\r`, so one CRLF of the separator survives into the body as a leading newline. Hash normalisation cannot undo a leading newline.

This is worse than before. I4 made the hash strict and `validateRecordFile` is wired into the pre-commit gate, so a Windows contributor is now blocked from committing files they never touched.

**Fix:** `/^---\r?\n([\s\S]*?)\r?\n---(?:\r?\n)+/` — one character. Add the regression test at file level, not on `computeContentHash`.

### B3. No recovery path once a record's hash is wrong

Making the hash strict was right, but the CLI offers `new`, `show`, `list` and `validate` — there is no `edit`, `rehash` or `--fix`. The only way to edit a record body is a text editor, and doing so now blocks every subsequent commit with a hash mismatch the contributor cannot repair except by computing SHA-256 by hand.

**Fix:** add `ruflo record rehash <id>`, or `--fix` on `validate`, before this gate ships. This is a small piece of work that turns an unusable gate into a usable one.

## Declared fixed, but not fixed

### I9. `predictedCostUsd` still passes `outputTokens: 0`

`model-router.ts:800,806` is unchanged in substance. The field was not renamed and not gated; a 22-line comment was added admitting it is a floor.

That would be a defensible "won't fix for now" if nothing consumed it. Something does: `plugins/ruflo-metaharness/scripts/router-parallel-analyze.mjs:152` uses `predictedCostUsd` as the counterfactual whenever the two routing branches disagree, and compares it against the other branch's **real** `actualUsd` at `:127`. Output tokens are 5x the input rate on every Claude model and usually dominate, so the comparison weighs a systematic under-estimate against a true figure. The bias runs one way — toward the neural branch passing the `cost < 1%` promotion gate at `:176`.

Either estimate output tokens, or gate the field so the analyser refuses to use it as a counterfactual. Documenting it is not sufficient while a promotion gate reads it.
